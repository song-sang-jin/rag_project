# RAG 파이프라인 설계

대상: 광주 청년. 도메인: 청년정책/지원사업. 기본 자료는 한국고용정보원 온통청년.
근거 질문: 아르바이트 중 신청 가능한가? 유사 지원과 중복 가능한가? 서류 발급일 기준은?

## 두 컬렉션

- `policy_meta_<embedding model hash>`: 정책번호를 ID로, 정책당 하나의 텍스트. 제목·분야·기관·지원내용·대상·기한·서류를 명시적 라벨로 결합. 조건검색을 위해 항목 텍스트를 청킹하지 않는다.
- `policy_docs_<embedding model hash>`: 참고 URL 및 웹 검색으로 수집한 공식 HTML/PDF 본문. 기본 정책 API 응답은 복제하지 않는다. ID `선택정책번호:문서ID:청크순번`. 같은 외부 문서를 다른 정책에 넣어도 덮어쓰지 않는다.
- 공통 메타데이터: policy_id, title, source, source_type, collected_at. 문서는 doc_id, query, chunk_index 추가.
- 본문 해시가 같으면 임베딩을 재사용. 변경된 문서의 잔여 청크는 제거.

## 수집

기본 목록 → 기관그룹/거주지역코드 필터 → 정책번호 중복 제거 → 누락 보고서 → 항목 임베딩.
질문 → 프롬프트1 웹 검색어 JSON → Tavily 웹 검색 → 제목·요약·URL 후보 → 프롬프트2 문서 ID JSON 선별 → HTML/PDF 본문 수집.
선택 정책은 이미 색인된 RAG 1 기본정보를 항상 근거로 사용한다. 질문 시 상세 API를 재조회하거나 같은 정책 텍스트를 RAG 2에 다시 색인하지 않는다.
정책 원본의 refUrlAddr1/2가 있으면 해당 본문을 우선 수집하고, 일반 질문에서도 관련 공고·FAQ 후보를 웹 검색한다.
웹 검색은 `TAVILY_API_KEY`가 필요하다. 키 누락·검색/본문 수집 실패는 경고하고 기본정보 및 기존 외부 근거로 진행한다.
웹 검색 캐시는 기존 정책명 검색 캐시와 분리한다. 검색 도메인은 policy_config.json의 web_domains로 제한한다.
SELECT는 자체 정책 공식 공고·안내의 own_policy_ids와 추가 관련 문서의 selected_ids를 분리한다. 정책명·기관·확인되는 연도/차수가 같은 문서만 자체 문서로 판정하도록 지시한다. 코드는 유효한 후보 ID만 받고, 자체 문서를 추가 문서 최대 3개 제한 밖에서 수집·색인한다. decisions에서 자체 문서로 표시했지만 목록에 누락한 경우에도 포함한다.
자체 문서는 100자 최소 길이/일반 HTML 텍스트 80,000자 절단을 적용하지 않는다. 빈 본문·접근 실패·지원하지 않는 형식·공개 주소/수집 규칙 위반 등 실제 수집 불가는 실패로 기록한다. API 응답 복제로 이 조건을 대체하지 않는다. 문서가 자체 정책에 해당하는지의 최초 판정은 LLM에 의존하며, 수집 성공이나 판정 정확성을 무조건 보장하지 않는다.
동일 검색어는 로컬 JSON 캐시를 사용하며 검색 요청을 반복하지 않는다. 외부 본문도 캐시한다.
추가 공식 URL은 HTML 본문/PDF 페이지별 추출, 출처 종류 구분. PDF는 페이지 번호를 제목과 URL fragment에 보존.

## 검색과 생성

### 세 프롬프트의 계약

| 단계 | 입력 | 출력과 역할 |
|---|---|---|
| 1 SEARCH | 선택 정책·질문·최근 대화 | `queries` JSON, 최대 3개. 최소 1개는 정책명·확인된 연도/차수를 보존한 자체 공식 문서 검색어 |
| 2 SELECT | 질문·후보의 ID/제목/요약/URL | `own_policy_ids`, `selected_ids`, `decisions` JSON. 자체 문서와 추가 0~3개를 구분하고 후보별 선택/제외 이유·적용 범위를 기록 |
| 3 ANSWER | 질문·최근 대화·번호가 붙은 근거 텍스트/유형/범위 | 한국어 답변과 `[근거 N]`. 근거 밖 사실은 추정하지 않음. 체크리스트는 같은 규칙에 JSON 형식을 추가 |

실제 지시문은 `youth_rag/prompts.py`에 있다. 조건 탐색용 EXPLORE는 위 세 단계 외에 별도로 사용한다. 임베딩 벡터는 생성 프롬프트에 전달하지 않는다.

LangGraph: `START → retrieve → generate → END`.
retrieve 내부에서 필요한 외부 문서를 준비한 뒤 선택 정책 메타데이터를 항상 포함한다.
외부 청크는 policy_id로 제한한 의미 유사도/MMR 검색, 본문 해시 중복 제거, 전체 Top-k 적용.
이전 API 상세 복제 청크는 검색 필터로 제외하며 백업 후 정리 스크립트를 제공한다. 출처 유형이 달라도 본문이 완전히 같으면 한 번만 전달한다.
generate는 프롬프트3에 현재 한국 날짜·선택 정책·대화·번호가 붙은 근거만 전달한다.
조건 미기재를 허용으로 해석하지 않으며 근거가 없으면 확인 불가라고 안내.
답변의 `[근거 N]`을 파싱하여 실제 인용된 유효 번호의 문서만 사용자에게 제시.
질문에서 명시한 공고 연도·차수를 grounding 모듈로 추출하여 문서 제목과 대조한다. 해당 범위의 근거가 검색되지 않거나 인용되지 않으면 확인 불가로 응답한다. 이는 연도·차수 혼입 방지 장치이며 일반적인 모든 사실의 참·거짓을 자동 증명하는 장치는 아니다.
UI의 대화 원본은 그대로 유지하며 모델에 전달하는 최근 메시지는 건당 500자로 제한한다. 답변 생성은 토큰 한도와 짧은 출력 지시를 적용하고, 생성이 길이 제한으로 중단되면 해당 내용을 완성된 답변으로 내보내지 않는다.

## 외부 호출과 처리 한도

공통 HTTP 모듈에서 호스트별 간격, 제한된 일시 오류 재시도, Retry-After 대기를 처리한다. 긴 서버 대기는 해당 요청을 종료하고 대기 중의 같은 호스트 요청도 생략한다.
PDF 추출은 별도 프로세스에서 시간·페이지 제한을 적용한다. 페이지별 문서 메타데이터는 보존하되 모든 페이지의 청크를 모아 최대 32개씩 임베딩한다.
같은 선별 입력은 selection_cache를 재사용하고, 실패 URL은 짧은 대기 캐시를 사용하여 반복 질문에서 같은 느린 페이지를 즉시 재요청하지 않는다.

## 조건 탐색과 특화 기능

사용자가 선택한 분야/기관 필터 → 항목 의미검색 20개 → LLM이 원문 조건을 대조해 적합 후보만 선별.
EXPLORE 응답은 후보 ID·eligible·reason을 포함하며 코드에서 eligible이 불리언 true인 항목만 표시한다. false·판정 누락·문자열 true는 제외한다. 설명의 명백한 제외 표현과 추천 판정이 모순인 경우도 보수적으로 제외한다. 표현 기반 검사는 모든 사실의 정확성을 보장하지 않는다. 사용자가 묻지 않은 '지금 신청' 조건을 임의로 추가하지 않도록 지시한다.
설명 가능한 후보가 없거나 조건 불명확이면 결과를 비워둔다. 정책 선택은 위젯 key+콜백 사용.
체크리스트는 별도 상상 생성 없이 같은 retrieve/generate 그래프로 서류·조건·신청 순서를 만든다.
정책 ID별 session_state로 대화를 분리한다.

## 설정 이유

1000자/200자 중복은 예외·서류 설명의 인접 맥락을 보존하는 시작점. 정책별 평균 문서 길이에 따라 비교 필요.
Top-k 6은 항목 1건을 보장하면서 상세 근거를 여러 개 제공하기 위한 시작점. 큰 값이 항상 정확한 것은 아니다.
MMR은 후보 20개 중 질문 관련성과 다른 청크와의 중복을 함께 고려한다(lambda 0.6).
