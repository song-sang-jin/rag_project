# PDF 요구사항 매핑

## 서비스 정의와 도메인 조건

- 서비스명: 청년이음. 대상: 광주 거주 청년 중 주거·취업·자산형성 등의 정책을 찾는 사용자.
- 데이터 범위: 온통청년 등록 중앙부처 및 광주권역 정책. 검증 자료 986건(중앙 657, 광주 329)으로 100건 이상 조건 충족.
- 근거가 필요한 질문: 신청 자격, 중복 참여, 제출서류, 신청기한·절차. 기본 안내에 없으면 공식 공고·FAQ·PDF에서 보완하며 확인하지 못한 정보는 추정하지 않는다.
- 출처 추적: 정책번호·기관·원문 URL·수집일을 보존한다. API 필드의 빈 값은 제한 없음으로 처리하지 않는다.
- 근거 형식: 정책당 한 문자열인 기본정보와 외부 HTML/PDF 청크를 분리하여 검색·인용한다.
- 선정 이유: 자격·예외를 원문에 근거해 설명해야 하므로 일반적인 추천보다 검색·출처 제시의 필요성이 명확하다. 모든 정책의 완전한 수록이나 최종 자격 판정은 범위 밖이다.

실행 결과·증빙은 아래 검증 결과에 함께 기록한다.

구현 완료와 실데이터/시각 검증 완료는 구분한다. 상호 체크리스트는 교육생이 직접 수행해야 한다.

## 셀프 체크리스트 및 남은 작업

최신 통합 집계: **통과 24·실패 0·미확인 0·해당없음 3**. 24번은 출처·이용 조건 기록과 배포 제외 범위를 README에 보완하여 재판정했다. 26번은 키·색인 누락 실제 화면과 내부 검사 화면을 추가하여 증빙 묶음을 완성했다. AI 모의 검토 결과이며 이용 권한의 법률적 보증이나 모든 답변의 정답 보장은 아니다.

제출 화면 점검 중 조건 탐색 모델이 제외 이유를 적은 항목도 결과 배열에 넣는 사례를 발견했다. 추천 판정 `eligible`을 JSON에 명시하고 코드에서 불리언 true만 허용하며, 설명에 '제외', '부합하지 않', '매치 불가'가 있는 항목도 걸러낸다. 제외·누락·문자열·모순 판정을 차단하는 회귀 테스트를 추가했다. 표현 기반 보수적 검사라 적합한 후보도 제외할 수 있으며, 모든 조건 판정을 사실 검증하는 기능은 아니다.

[통합 점검 결과](../outputs/20261023_checklist/청년이음_통합체크리스트.xlsx)는 최신 증빙을 반영한다. 24번은 README의 출처·이용 조건 기록, 26번은 화면 및 내부 결과 증빙의 첨부를 기준으로 확인한다. 모든 외부 문서의 재배포 허락·모든 질문의 정답 보장을 뜻하지 않는다. AI 모의 상호 피드백은 교육생 간 실제 상호 점검과 구분한다.

## 재현

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe policy_cli.py status
.\.venv\Scripts\python.exe -m streamlit run app.py
```

실환경 전체 호출은 `scripts/smoke_live.py`로 가능하다. `.env`와 외부 연결이 필요하고 모델 사용량 및 캐시·DB 변경이 발생한다. 상세 검증 로그는 `outputs/20261023_checklist/evidence/`에 보존한다.
